# ADR 015: Cloudflare Edge Proxy, DDoS Protection, and Custom Domain Mapping

## Status
Accepted

## Context
Following the deployment of the Streamlit presentation layer to DigitalOcean App Platform (ADR-014), the application was exposed to the public via an autogenerated domain (`sf-yt-metrics-5u96c.ondigitalocean.app`). 

Sharing this link publicly introduced two distinct concerns:
1. **Container Resource & Bandwidth Exhaustion:** The DigitalOcean Basic tier provisions a single container (1 vCPU, 2 GB RAM) with a 200 GB monthly bandwidth quota. Public exposure exposes the container directly to bot crawlers, search spiders, and potential DDoS attacks, which could spike CPU/RAM or exhaust bandwidth.
2. **Branding & Longevity:** An autogenerated vendor subdomain looks unpolished on resumes and portfolios, and locks the public interface to a specific cloud provider's URL scheme.

## Decision
We will route all public traffic through **Cloudflare** as a reverse proxy, CDN, and DNS management layer, bound to the custom domain **`https://ytmetrics.matudata.com`**.

### Why Cloudflare?
1. **Zero Financial Cost:** Cloudflare’s permanent Free tier provides unmetered DDoS mitigation, automated bot challenges, and global DNS routing at no charge.
2. **Edge Asset Caching:** Cloudflare caches static assets (Streamlit JavaScript bundles, CSS stylesheets, fonts, Altair assets) at 300+ edge locations worldwide, saving the origin container's 200 GB bandwidth.
3. **Native WebSocket Streaming:** Streamlit depends on persistent WebSocket connections (`_stcore/stream`), which Cloudflare natively supports out-of-the-box.
4. **Professional Identity & Provider Agnostic:** Binding `ytmetrics.matudata.com` allows the project to be showcased professionally. If the hosting infrastructure ever shifts in the future (e.g., to AWS, GCP, or bare metal), the public URL remains invariant.

## Configuration & Anti-Pitfall Standards
* **DNS Record:** A `CNAME` record for `ytmetrics` pointing to `sf-yt-metrics-5u96c.ondigitalocean.app` with Cloudflare Proxy mode enabled (Orange Cloud ☁️).
* **SSL/TLS Encryption Mode:** Strictly configured to **Full** (or **Full (Strict)**). Setting mode to "Flexible" is prohibited as DigitalOcean origin enforces HTTPS, which triggers an infinite `ERR_TOO_MANY_REDIRECTS` loop.
* **WebSocket Support:** Explicitly enabled under Cloudflare Network settings.

## Consequences
* **Positive:** Complete DDoS and crawler protection for the single 2GB RAM container.
* **Positive:** Static bandwidth offloaded from DigitalOcean to Cloudflare's global edge network.
* **Positive:** Professional custom branding for Milestone 1 public demo.
* **Neutral:** Origin app maintains automated GitHub CI/CD deployments through DigitalOcean without requiring reconfiguration.
